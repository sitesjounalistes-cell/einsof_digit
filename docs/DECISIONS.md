# Décisions d'architecture — consignées conformément à la section 20.12 du cahier des charges

| Date | Contexte | Choix | Raison |
|------|----------|-------|--------|
| 2026-10-14 | Environnement sandbox : une seule route exposée (`/`), pas de `next build` | **Architecture mono-page** : toutes les sections (accueil, services, SaaS, tarifs, FAQ, à propos, contact…) sont des ancres de la route `/` avec `data-section-id` stables | Contrainte de l'environnement d'exécution ; le registre `src/lib/sections-registry.ts` conserve la structure prévue pour une migration multi-routes (`/fr/services`…) sans refactorisation majeure |
| 2026-10-14 | Section 24 impose PostgreSQL + Drizzle + pgvector/Neon | **Prisma + SQLite** (fichier `db/custom.db`) | Prisma/SQLite est la stack imposée par l'environnement sandbox ; les tables reprennent fidèlement le modèle de la section 24 (leads, lead_events, trial_requests, contact_messages, chat_sessions, chat_messages, consents, analytics_events) |
| 2026-10-14 | Chatbot : pgvector + recherche sémantique prévus (sections 9.2/13) | **Base de connaissances en contexte direct** (`src/lib/chatbot/knowledge.ts`) : la base entière (tarifs exacts, politiques, FAQ) est injectée dans le prompt système | SQLite ne supporte pas pgvector ; la base de connaissances reste de taille maîtrisée (~2 k jetons). La vectorisation (`kb_chunks` + HNSW) est reportée à la migration PostgreSQL |
| 2026-10-14 | Streaming LLM SSE prévu (section 25) | Le SDK `z-ai-web-dev-sdk` n'expose pas de streaming : réponse complète côté serveur, puis **re-diffusion SSE mot à mot** (22 ms/token) | Préserve l'expérience « texte au fil de l'eau » exigée (32.9) ; les actions outils sont parsées via marqueurs `[[action:{…}]]` validés côté serveur |
| 2026-10-14 | Auth admin : Auth.js + argon2 + TOTP obligatoire (section 26) | **Version simplifiée** : mot de passe serveur (`ADMIN_PASSWORD`) + cookie httpOnly signé SHA-256, session 8 h, rate-limit 5/5 min | Sandbox sans fournisseur d'e-mail/SMS pour le TOTP ; le contrôle d'accès reste effectif côté API. Production : basculer sur Auth.js + TOTP (tâche H-03/H-10) |
| 2026-10-14 | Mode Omnis prévu en v1.5 (section 18/29) | **Omnis livré dès cette version** avec Web Speech API navigateur (reconnaissance + synthèse), replis denied/unsupported/texte | La spec §27 définit déjà l'implémentation navigateur par défaut ; l'architecture mono-route rend le mode immédiatement démontrable |
| 2026-10-14 | Notifications push web-push + VAPID (sections 6/14/28) | **Non implémenté** — nécessite clés VAPID + serveur push (tâches humaines H-03/H-05) | L'UI PWA (manifest, service worker, bannière d'installation, guide iOS) est livrée ; l'abonnement push s'ajoutera sans refonte |
| 2026-10-14 | Sections partenaires / témoignages / réalisations / documents | **Masquées** tant qu'aucun contenu réel n'est publié (données absentes) | Règle stricte §20.4 : ne jamais inventer de client, partenaire ou témoignage |
| 2026-10-14 | Multilingue 5 langues avec préfixe d'URL (section 21) | **Sélecteur client** (fr source complet, en complet, es/zh/de partiels) avec **repli sur fr** conformément au §25 ; détection Accept-Language, mémorisation localStorage | Le routage par préfixe d'URL est impossible en mono-route ; les traductions partielles sont marquées pour relecture humaine (H-09) |
| 2026-10-14 | Hébergement Vercel/Neon/R2/Resend/Upstash (section 21) | Adaptateurs réduits au minimum sandbox : rate-limit en mémoire, pas de file QStash, e-mails non câblés | Les tâches humaines H-03 (comptes) conditionnent ces intégrations ; les points d'insertion sont isolés (API routes + lib/) |
| 2026-10-14 | Nom de l'entreprise | Variable `NEXT_PUBLIC_BRAND_NAME` (défaut provisoire **EINSOF**, cf. en-tête du cahier des charges), jamais écrit en dur | §20 précisions |
